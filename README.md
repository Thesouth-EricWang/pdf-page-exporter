# PDF / Word 页面导出工具（原生版）

把 PDF 或 Word 文档的指定页导出成图片。给需要交证明材料、整理证书截图的人用。

单文件 exe，纯原生实现，**不装 Python、不写注册表、退出不留残留**。

---

## 拿来就用

下载后把这两个文件放在**同一个目录**里，双击 exe：

```
PDFPageExporter.exe     ← 双击这个
pdfium.dll              ← 必须和 exe 放在一起
```

- 系统要求：**Windows 7 及以上**
- 不需要安装任何运行库（exe 用静态 CRT 编译）
- 不需要管理员权限

仓库里有两种架构，**不确定就选 `bin\x86`**（32 位）：

| 目录 | 架构 | 适用 |
|---|---|---|
| `bin\` | 64 位 | 现代电脑，渲染大图更宽松 |
| `bin\x86\` | 32 位 | 兼容面最广，64 位系统上照样跑 |

**exe 和 pdfium.dll 的架构必须一致**，不能混搭。

想改 exe 的名字随便改，只要 `pdfium.dll` 还在旁边就行。

## 怎么用

1. 点 **添加…** 选文件，或者**把文件直接拖进窗口**（可以一次拖多个）
2. 填**页码范围**
3. 选格式、压缩档、分辨率
4. 点 **开始导出**

导出结果默认放在**程序自己所在目录**下，每个文档一个同名文件夹：

```
PDFPageExporter.exe
pdfium.dll
加分证明/                        ← 与源文件同名
  ├── 加分证明-第1页.jpg
  └── 加分证明-第3页.jpg
```

图片名 = `文件名-第N页.扩展名`。想放别处就在「输出目录」里选。

### 页码范围写法

| 写法 | 含义 |
|---|---|
| 留空 / `全部` / `*` | 整份导出 |
| `3` | 第 3 页 |
| `1,3,5` | 第 1、3、5 页 |
| `5-7` | 第 5 到 7 页 |
| `7-5` | 倒着写也认，等价于 `5-7` |

重复页码自动去重，超出总页数会明确报错。批量导出时一个文件失败不会中断其余，最后统一汇报。

## 三个设置怎么选

### 压缩（1-100，默认 85）

扫描版 PDF 的内页本身就是一整张 JPEG。用 PNG 导出，等于把已经压过的照片再无损存一遍，体积会翻好几倍。真正省空间靠的是 JPG 质量。

同一页、300 dpi 实测：

| 格式 | 压缩档 | 单页大小 |
|---|---|---|
| PNG | 无损 | 2.15 MB |
| JPG | 98 | 1.30 MB |
| JPG | 85 | 0.69 MB |
| JPG | 60 | 0.48 MB |

### 分辨率：自动识别

默认的「自动」不是拍脑袋给个 300，而是真的去量原图。

原理：PDF 里的图是像素，在页面上占一块物理尺寸。**像素数 ÷ 占位的英寸数 = 这张图被印上去时的实际 dpi**。按这个值重新渲染就是 1:1，既不插值放大也不缩水。

扫描版的证明通常测出来是 **400 dpi**。纯文字页（比如 Word 转出来的 PDF）没有位图可反推，退回 300 dpi。

想体积小一点，手动选 300 或 150。

### 扫描页会走「无损提取」

如果你的页是整页一张 JPEG 扫描图，且选的是 JPG + 压缩档 ≥ 90，程序会**直接把内嵌的原始 JPEG 字节抠出来**，不重新编码。输出的图和源文件里的图**逐字节一致**，而且快得多。

这也是为什么压缩档设在 90 以下时会改用渲染：你要的是压小，那就得重编码。

## Word 文档支持

`.docx` `.doc` `.docm` `.rtf` `.odt` 都能拖进来，用法和 PDF 完全一样。

内部流程：调本机 Microsoft Word 把文档另存为临时 PDF → 按页出图 → **删掉临时 PDF**。

- **需要本机装了 Microsoft Word**，没装会明确报错
- 每个文件转换要几秒
- 临时文件用完即删，不留痕迹

## 从源码构建

需要 Visual Studio 2019/2022，安装时勾选「使用 C++ 的桌面开发」+ Windows SDK。

```bat
build.bat          :: 64 位，输出到 bin\
build.bat x86      :: 32 位，输出到 bin\x86\
```

如果自动找不到 `vcvars64.bat` / `vcvars32.bat`，先设好环境变量：

```bat
set VCVARS=C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Auxiliary\Build\vcvars64.bat
build.bat
```

### 目录结构

```
├── src/
│   ├── app.h          公共声明
│   ├── core.cpp       PDFium 绑定、导出逻辑、Word 转换
│   └── main.cpp       Win32 界面
├── include/           PDFium 头文件（32/64 位通用）
├── bin/               64 位产物（exe + pdfium.dll）
├── bin/x86/           32 位产物
├── licenses/          第三方许可证
└── build.bat
```

### 想换成别的 pdfium 版本

`include/` 和两个 `pdfium.dll` 来自 [bblanchon/pdfium-binaries](https://github.com/bblanchon/pdfium-binaries)。换版本时按架构分别换。

## 关于 pdfium.dll

PDF 渲染必须有渲染器，而纯原装的 Windows 里没有。所以这里打包了 Google 的 PDFium（Chrome 用的那个 PDF 引擎）。

- 体积：**7.0 MB（64 位）/ 6.5 MB（32 位）**，是整个程序体积的主要来源。exe 本身只有 **170-220 KB**。
- 协议：BSD-3-Clause，许可证见 `licenses/`。

**为什么不做成单个 exe？** 把 DLL 塞进 exe 里，运行时还是得解压到临时目录才能加载，那正是「残留文件」的来源。分开放两个文件，运行时零解压、零残留。想只发一个文件的话，把它压缩成 zip 就行。
